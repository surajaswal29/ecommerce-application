# API Endpoints Constants

This directory contains centralized API endpoint definitions for the ecommerce
application.

## Files

- `apiEndpoints.js` - Main constants file with all API endpoint definitions
- `apiEndpoints.example.js` - Usage examples and helper functions
- `README.md` - This documentation file

## Overview

The API endpoints are organized into the following categories:

### 1. User Management (`USER`)

- Authentication (register, login, logout)
- Password management (forgot, reset, update)
- Profile management (get, update, upload image)
- Admin user management (CRUD operations)

### 2. Product Management (`PRODUCT`)

- Public product access (list, details)
- Product reviews (create, get, delete)
- Admin product management (CRUD operations)

### 3. Shopping Cart (`CART`)

- Add items to cart
- Get cart contents
- Update cart items
- Remove cart items

### 4. Order Management (`ORDER`)

- Create new orders
- Get order details and user orders
- Admin order management (list, update, delete)

### 5. Payment Processing (`PAYMENT`)

- Create payment requests
- Handle payment webhooks
- Check payment status

### 6. File Upload (`UPLOAD`)

- Single and multiple file uploads
- Image deletion
- Upload statistics

## Usage

### Basic Usage

```javascript
const { API_ENDPOINTS } = require('./constants/apiEndpoints');

// Access specific endpoint
const loginEndpoint = API_ENDPOINTS.USER.LOGIN;
console.log(loginEndpoint.path); // '/user/login'
console.log(loginEndpoint.method); // 'POST'
console.log(loginEndpoint.auth); // false
```

### Helper Functions

```javascript
const {
  getFullUrl,
  getEndpoint,
  getEndpointsByCategory,
  requiresAuth,
  getRequiredRoles,
} = require('./constants/apiEndpoints');

// Get full URL
const fullUrl = getFullUrl(API_ENDPOINTS.USER.LOGIN.path);
// Returns: 'http://localhost:4000/api/v1/user/login'

// Get endpoint by category and key
const loginConfig = getEndpoint('USER', 'LOGIN');

// Get all endpoints for a category
const userEndpoints = getEndpointsByCategory('USER');

// Check authentication requirements
const needsAuth = requiresAuth('USER', 'GET_MY_DETAILS'); // true

// Check role requirements
const requiredRoles = getRequiredRoles('USER', 'GET_ALL_USERS'); // ['admin']
```

### Frontend Integration

```javascript
// API client using constants
const apiClient = {
  login: async (credentials) => {
    const endpoint = API_ENDPOINTS.USER.LOGIN;
    const response = await fetch(getFullUrl(endpoint.path), {
      method: endpoint.method,
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(credentials),
    });
    return response.json();
  },

  getProducts: async (params = {}) => {
    const endpoint = API_ENDPOINTS.PRODUCT.GET_ALL_PRODUCTS;
    const url = new URL(getFullUrl(endpoint.path));
    Object.keys(params).forEach((key) =>
      url.searchParams.append(key, params[key])
    );
    return fetch(url.toString()).then((res) => res.json());
  },
};
```

### Express Route Integration

```javascript
const { API_ENDPOINTS } = require('./constants/apiEndpoints');

// Use constants in route definitions
app.get(
  API_ENDPOINTS.PRODUCT.GET_ALL_PRODUCTS.path,
  productController.getAllProducts
);
app.post(API_ENDPOINTS.USER.REGISTER.path, userController.registerUser);

// With middleware
app.get(
  API_ENDPOINTS.USER.GET_MY_DETAILS.path,
  isAuthenticatedUser,
  userController.getUserDetails
);
```

## Endpoint Structure

Each endpoint object contains:

```javascript
{
  path: '/api/endpoint/path',     // The endpoint path
  method: 'GET|POST|PUT|DELETE',  // HTTP method
  auth: true|false,               // Authentication required
  roles: ['admin'],               // Required roles (optional)
  description: 'Endpoint description' // Human-readable description
}
```

## Benefits

1. **Centralized Management**: All endpoints defined in one place
2. **Type Safety**: Consistent structure across all endpoints
3. **Easy Maintenance**: Update endpoints in one location
4. **Documentation**: Self-documenting with descriptions
5. **Validation**: Helper functions for endpoint validation
6. **Environment Flexibility**: Easy to switch between environments

## Environment Configuration

```javascript
const getApiConfig = (environment = 'development') => {
  const baseUrls = {
    development: 'http://localhost:4000',
    staging: 'https://staging-api.myapp.com',
    production: 'https://api.myapp.com',
  };

  return {
    baseUrl: baseUrls[environment],
    endpoints: API_ENDPOINTS,
  };
};
```

## Migration Guide

To migrate existing hardcoded endpoints:

1. Replace hardcoded paths with constants:

   ```javascript
   // Before
   app.get('/api/v1/product/products', productController.getAllProducts);

   // After
   app.get(
     API_ENDPOINTS.PRODUCT.GET_ALL_PRODUCTS.path,
     productController.getAllProducts
   );
   ```

2. Update frontend API calls:

   ```javascript
   // Before
   fetch('http://localhost:4000/api/v1/user/login', { ... });

   // After
   fetch(getFullUrl(API_ENDPOINTS.USER.LOGIN.path), { ... });
   ```

3. Use helper functions for validation and checks:

   ```javascript
   // Before
   if (endpoint === '/user/me') {
     /* check auth */
   }

   // After
   if (requiresAuth('USER', 'GET_MY_DETAILS')) {
     /* check auth */
   }
   ```
