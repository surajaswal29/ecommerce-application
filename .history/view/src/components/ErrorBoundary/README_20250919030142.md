# Error Boundary Implementation

This directory contains the React Error Boundary implementation for the ecommerce application.

## Components

### ErrorBoundary.jsx
The main error boundary class component that catches JavaScript errors in the React component tree and displays a fallback UI.

**Features:**
- Catches errors during rendering, lifecycle methods, and constructors
- Generates unique error IDs for tracking
- Logs errors to console and external services
- Provides retry functionality
- Integrates with error logging utilities

### ErrorPage.jsx
A user-friendly error page component that displays when an error is caught.

**Features:**
- Clean, responsive design with Bootstrap styling
- Error ID display for support purposes
- Retry and "Go Home" buttons
- Collapsible technical details section
- Copy error details functionality
- Help section for users

### ErrorPage.css
Styling for the error page with:
- Modern gradient background
- Responsive design
- Smooth animations
- Professional error UI

### ErrorTestComponent.jsx
A test component for demonstrating error boundary functionality.

**Usage:**
```jsx
import ErrorTestComponent from './components/ErrorBoundary/ErrorTestComponent';

// Add to any route temporarily for testing
<Route path="/test-error" element={<ErrorTestComponent />} />
```

## Utilities

### errorLogger.js
Centralized error logging utility with support for:
- Console logging in development
- External service integration (Sentry, LogRocket, etc.)
- Local storage for debugging
- Google Analytics integration
- Custom API endpoints

### use-error-logger.js
React hook for error logging (for functional components).

## Integration

The ErrorBoundary is integrated at the app level in `App.jsx`:

```jsx
import ErrorBoundary from './components/ErrorBoundary/ErrorBoundary';

function App() {
  return (
    <ErrorBoundary>
      {/* Your app content */}
    </ErrorBoundary>
  );
}
```

## Error Tracking Services

The error logger supports integration with various services:

### Sentry
```javascript
// Add to your app initialization
import * as Sentry from "@sentry/react";

Sentry.init({
  dsn: "YOUR_SENTRY_DSN",
});
```

### LogRocket
```javascript
// Add to your app initialization
import LogRocket from 'logrocket';

LogRocket.init('YOUR_APP_ID');
```

### Custom API
Uncomment and modify the API endpoint in `errorLogger.js`:

```javascript
fetch('/api/errors', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(errorData)
}).catch(console.error);
```

## Best Practices

1. **Error Boundary Placement**: Place error boundaries strategically around major sections of your app
2. **Error Logging**: Always log errors for debugging and monitoring
3. **User Experience**: Provide clear error messages and recovery options
4. **Testing**: Regularly test error scenarios to ensure proper handling
5. **Monitoring**: Set up alerts for critical errors in production

## Limitations

- Error boundaries only catch errors in React components during rendering, lifecycle methods, and constructors
- They do not catch errors in:
  - Event handlers
  - Async code (setTimeout, promises, etc.)
  - Server-side rendering
  - Errors thrown in the error boundary itself
